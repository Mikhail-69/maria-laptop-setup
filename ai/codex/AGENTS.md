## Стиль работы

Перед началом работы читай `/home/mikhail/обо мне.md` и учитывай предпочтения пользователя и контекст его целей и проектов.

- **Сначала сообщи краткий план**, если задача сложнее одной правки; продолжай без ожидания согласования.
- **После обычных изменений покажи итоговый diff или краткое описание.** Перед рискованными изменениями покажи diff и согласуй последствия.
- **После изменений убедись**, что проект собирается или проходит линтер.
- **Никогда не коммить и не пушить** без явного разрешения.
- **Не удаляй пользовательские данные** без разрешения. Собственные временные файлы и воспроизводимые build/cache-артефакты можно очищать в рамках задачи.
- **Уточняй существенную неопределённость**; обычные детали решай самостоятельно.

## Автономность и подтверждения

- Запрос пользователя разрешает необходимые обычные шаги в рамках задачи: чтение кода и документации, редактирование файлов, установку зависимостей проекта, сборку, тесты, линтер и диагностику.
- Сообщай краткий план и продолжай без ожидания согласования. Обычные технические решения принимай самостоятельно. Уточняй только существенную неопределённость результата, стоимости, сохранности данных или архитектуры.
- Подтверждение требуется для необратимой потери пользовательских данных, массового удаления, переписывания Git history, публикации личных данных, платных операций, изменения прав доступа и существенных изменений production или работающих сервисов, если конкретное действие ещё не разрешено.
- Прямой запрос на конкретное действие уже является разрешением. Не спрашивай повторно в рамках согласованного объёма. Commit и push выполняй только по явному запросу.
- Собственные временные файлы и воспроизводимые build/cache-артефакты можно очищать в рамках задачи. Пользовательские файлы и несохранённые изменения сохраняй.
- Перед рискованным действием подготовь конкретный результат и объясни последствия. Diff обычных правок показывай после выполнения.
- Различай вопросы пользователю и технические approvals sandbox. Ограничения среды соблюдай, не обходи. Секреты и файлы аутентификации без отдельного разрешения не читай и не раскрывай.

## Безопасность

### Запрещено

- Читать и изменять `.env`, `.secrets` без разрешения.
- Работать с `~/.ssh/`, `~/.aws/`, `~/.config/gh/` без разрешения.
- Выполнять `sudo`, `rm -rf /`, `shutdown`, `reboot`, `mkfs`.
- Коммитить секреты, токены, ключи.
- Публиковать личные данные без подтверждения.

### Проверка на секреты

Перед коммитом убедись, что в диффе нет:
- `password`, `secret`, `key`, `token`, `api_key`, `JWT`.
- Путей к `.env`, `id_rsa`, `credentials`.
- Хардкод-токенов (`ghp_xxx`, `AKIAxxx`).

Если нашёл — **останови работу и предупреди пользователя**.

## Визуал и ассеты

### Эмодзи

- **Не используй эмодзи** в ответах, заголовках Markdown, коммит-сообщениях и комментариях к коду.
  Используй только текст или иконки из списка ниже.
- Эмодзи не считаются иконками: в UI, в документации и в README их тоже быть не должно.
- Исключение — цитата пользователя или содержимое внешнего файла, которое нельзя менять (логи, вывод CLI).

### Источники иконок

| Библиотека | URL | Лицензия | Атрибуция |
|------------|-----|----------|-----------|
| Lucide | https://lucide.dev/icons/ | ISC | не нужна |
| Tabler Icons | https://tabler.io/icons | MIT | не нужна |
| Phosphor Icons | https://phosphoricons.com/ | MIT | не нужна |
| Iconoir | https://iconoir.com/ | MIT | не нужна |
| Hugeicons (Free, Stroke Rounded) | https://hugeicons.com/ | MIT | не нужна |

Примечание: у Hugeicons Pro и Lordicon PRO свои лицензии — их условия действуют только при покупке.

### Правила работы с иконками

1. **Сначала проверь библиотеки.** Прежде чем рисовать иконку самому (SVG руками, генерация path, «на глаз»)
   найди её в списке выше. Иконки из этих наборов — дефолт.
2. **Нет иконки — скажи об этом.** Если в библиотеках подходящей иконки нет:
   - прямо сообщи пользователю, что иконка не найдена;
   - **не выдумывай** её и **не подставляй** случайную или похожую по смыслу иконку;
   - оставь элемент без иконки и предложи варианты (текст, другое название, новый набор).
3. **Не придумывай API.** Имена иконок, экспорты и компоненты проверяй по документации библиотеки —
   не сочиняй `import { RocketIcon } from "lucide-react"`, если такого экспорта нет.
4. **Не меняй геометрию иконок.** Не перерисовывай, не вытягивай пути, не меняй пропорции —
   только `size`, `color`, `strokeWidth` из API библиотеки.
5. **Анимацию показывай в доступном браузерном preview Codex**. Используй фактически доступный browser tool; не выдумывай API `browser.preview`. Если preview недоступен, сообщи об этом.
6. Спорную или новую библиотеку иконок предлагай пользователю, а не добавляй молча в зависимости.

## Настройки Codex

- Глобальная конфигурация: `~/.codex/config.toml`; глобальные инструкции: `~/.codex/AGENTS.md`.
- Читай проектные `AGENTS.md` и `AGENTS.override.md` по иерархии рабочего каталога; более близкие инструкции уточняют глобальные.
- Skills ищи через доступный каталог Codex, в том числе `~/.agents/skills`; не копируй их повторно из Claude Code или OpenCode.
- Для документации библиотек используй подключённый Context7, для GitHub — доступный GitHub connector/MCP, для браузерных проверок — доступные browser tools.
- Не переноси буквально названия инструментов Claude Code (`Bash`, `Edit`, `Write`) в вызовы Codex: используй реальные инструменты текущей сессии.
- Не читай файлы аутентификации Codex, Claude Code и OpenCode, каталоги `secrets/` и значения ключей без явного разрешения.
- Sandbox и approval policy обеспечиваются Codex; инструкции в Markdown их не заменяют. Сохраняй `workspace-write` и `on-request`, если пользователь не попросил иное.
- Локальные command hooks действуют только в поддерживающей их среде Codex; в cloud-сессиях не считай их гарантированной защитой.
